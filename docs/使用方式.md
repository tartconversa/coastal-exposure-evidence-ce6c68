# 分析应用使用方式（sealpack）

面向产品经理与试验站的内部工程决策应用。**不签发法定认证，不把加速试验小时换算成
服役年限，不把不同协议混成一个通过率。** 所有结论都可追溯到观测区间与剔除理由。

## 1. 运行约定

资料目录通过 `--data` 显式传入，Python 以隔离模式运行，避免数据目录中的同名模块被
导入；全局参数（自助次数、随机种子）放在子命令之前：

```bash
python3 -I seal --replicates 500 --seed 7123 run --data /workspace
```

同输入、同种子的两次运行结果逐字节一致（除 `generated_at` 时间戳）。`--json` 输出
机器可读结构，`--out` 落盘；默认输出人可读报告。试验安排、自定义条件等业务输入放在
`work/` 目录，与 `data/` 原始资料分离。

## 2. 可重复分析运行

```bash
python3 -I seal run --data /workspace --json --out work/runs/run_$(date +%F).json
```

输出包含五部分，每个数值都带样本量、失效数、删失构成与记录级溯源句柄：

1. **试验室证据**：按 (设计, 协议) 的区间删失估计，时间单位为暴露小时；
2. **防偏诊断**：本资料中设计与盐雾剖面完全混杂（D1/D2/D3 各自只承受一种烈度），
   朴素通过率会把高暴露早停的设计错误排前，应用同时给出两套口径并禁止用朴素排名承诺；
3. **现场证据单元**：按 (设计, 环境) 的区间删失估计，时间单位为服役日；
4. **客户用途评估**：逐设计、逐环境的四级承诺结论；
5. **同环境设计比较**：只有同一现场环境下都有证据的设计才可比，无证据者保留未知、
   不参与排名。

历史时点复算用 `--as-of`，晚于该时点的巡检与现场经历会被剔除并在输出中计数：

```bash
python3 -I seal run --data /workspace --as-of 2025-02-01T00:00:00+08:00
```

## 3. 统计口径（为什么这样分级）

- 腐蚀是**区间结局**：试验室只知发生在末次 clear 与首次 corrosion 两次巡检之间；
  现场只知发生在 `last_clear_day` 与 `last_seen_day` 之间。估计量是非参数 Turnbull
  自洽算法，含开放末端桶承接右删失个体的存活质量，不做参数寿命外推。
- 不确定度用**整群自助**：试验室按制造批重采样（同批试样相关），现场按设备重采样。
  零失效单元的自助上界退化为零时，改用保守上界 `1-(1-level)^(1/n)`，不把“没看到”
  说成“风险为零”。
- 超出最大随访的时长一律 `unidentifiable`，不插值、不外推。

四级语义（逐单元、给定时长与风险上限）：

| 状态 | 含义 | 触发条件 |
| --- | --- | --- |
| supported | 支持 | 点估计与自助上分位都在上限内，且样本量 ≥ 6 |
| limited | 支持范围有限 | 点估计合格但不确定度越界，或样本量不足 |
| adverse | 观测到较差表现 | 点估计本身已超过上限（与 limited 严格区分） |
| unknown | 尚不支持 | 该工况无证据，或时长超出最大随访 |

总体承诺按需求构成加权，但**任一环境 unknown 时整体不得判支持**，未覆盖环境单独列出，
不被平均风险掩盖。

## 4. 承诺查询与销售台账

按资料中的用途查询，或提交自定义条件（`share` 之和必须为 1）：

```bash
python3 -I seal query --data /workspace --request R1
python3 -I seal query --data /workspace --conditions work/conditions_coastal_180.json
```

客户可接受的两种让步，应用分别量化对风险与可接需求的影响：

```bash
# 缩小适用环境：剔除 humid/inland，权重在保留环境上重归一化，柜数按保留比例折算
python3 -I seal scenario --data /workspace --request R1 --kind narrow --drop humid,inland
# 降低承诺时长：在新时长上重新评估全部环境单元
python3 -I seal scenario --data /workspace --request R3 --kind reduce --duration 180
```

冻结承诺时，销售当时采用的证据、限制与资料指纹一并写入只追加台账；unknown 工况
不能保存为承诺：

```bash
python3 -I seal save --data /workspace --ledger work/ledger \
    --conditions work/conditions_coastal_180.json --design D1 --note "首批沿海180天"
python3 -I seal list --ledger work/ledger
```

资料补入失效检查或设计更正后，**原快照不改写**，重评只输出影响清单：

```bash
python3 -I seal impact --data <新资料目录> --ledger work/ledger
```

需要变更已发承诺时走显式换版，新快照通过 `supersedes` 引用原编号，旧快照标记
`superseded` 并保留原解释：

```bash
python3 -I seal supersede --data <新资料目录> --ledger work/ledger \
    --old-commitment CMT-XXXXXXXX --conditions work/conditions_v2.json --design D1
```

## 5. 试验安排

安排文件是一份 JSON 计划，每个 placement 给出舱段、动作与试样。硬约束校验：

```bash
python3 -I seal plan-validate --data /workspace --plan work/plans/plan_a.json
# 多份销售请求联排，自动检查同一试样被重复占用
python3 -I seal plan-validate --data /workspace \
    --plan work/plans/plan_a.json work/plans/plan_b.json
```

硬约束包括：动作/舱段/试样三方协议一致（转舱允许但前序暴露不抹掉）、舱位容量
（含其他项目 reserved）、已破坏试样不得再排、破坏性动作执行后试样即消耗、同一试样
不得时间重叠或跨请求重复占用、总费用不超预算、舱段不早于安排决策日。

缺口与情景：

```bash
# 当前承诺缺口（现场缺口明确标注不能由试验室排舱关闭，因无加速换算）
python3 -I seal plan-gaps --data /workspace --request R1
# 安排若执行的覆盖变化；未来结局只作 hypothetical，不预支为证据
python3 -I seal plan-scenario --data /workspace \
    --plan work/plans/plan_a.json --request R1
# 舱位/试样被其他项目占用后重新判断可兑现范围
python3 -I seal plan-recheck --data /workspace \
    --plan work/plans/plan_a.json --request R1 \
    --overrides work/plans/occupancy_override.json
```

## 6. 业务检查如何对应判断

`tests/test_business.py` 用可执行断言固化了需求中的关键判断，可用
`python3 -m unittest discover -s tests -v` 复跑：

- **停试三因不合并**：safety/machine/planned 在删失计数中分别保留，现场 seal_change
  与 censored 也分别保留；
- **密封换型**：同一设备换密封后新段必须归属不同设计、从旧段终止日另起局部时钟，
  后续经历不算原设计完整寿命；
- **区间腐蚀**：所有失效观测都是 `left < right` 的区间，不存在精确失效时刻；
- **“有限支持”与“较差表现”分开**：D3 humid 点风险 12.5% 超 5% 上限判 adverse；
  D1 coastal 在 10% 上限下点估计合格但上分位越界判 limited；
- **未知不被平均掩盖**：R1/R2 每个设计都有完全无证据的环境，整体一律 unknown；
  R3 时长 360 天超过现场最大随访 320 天，全部 unknown；
- **防偏**：朴素通过率把 D1 排第一，区间删失口径排名不同，应用强制告警；
- **资源竞争**：多计划重复占用同一试样、破坏后延续暴露、协议混挂、容量超员均被拒绝；
  资源被占后已发承诺不改写，只是补证延后；
- **情景不等于证据**：`plan-scenario` 的每个未来结局都带 `evidence_now=false`。
